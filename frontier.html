Scraping Guards — Frontier (47–82)

Prefer a realistic target? The recipe fixture is an ordinary-looking recipe page — servings calculator, 20 steps, JSON-LD — with a handful of these guards switched on the way a real site would have them.

Guards 47–82 extend the suite past the original 46. Blue = architectural, orange = simulated stub. Base pages: index.html (0–25), advanced.html (26–46).

72. Subtle data perturbation

Guard 54 fabricates whole records, which a scraper eventually notices — nothing reconciles. This returns the real catalogue with small deterministic drift: prices off by a few percent, stock flags sometimes flipped. Right shape, right magnitudes, consistent across re-fetches.

No marker field, unlike guard 54 — a marker is the one thing that would give it away. Provenance comes from the canary (41) instead.

[fetching…]

73. Per-character rendering

Every character is drawn into its own canvas, delivered in shuffled DOM order, with CSS order restoring the reading sequence. Even OCR over individual elements yields scrambled characters.

[loading…]

74. Tiered field-level access

Quota caps how much a scraper takes; this caps how much detail any account can see. Farming free accounts yields a strictly poorer dataset — premium fields are never in the response.

[checking…]

75. Verified crawler allowlisting

The counterpart to guard 47: every other guard blocks, this one lets the right bots through. A Googlebot UA is trivially forged, so it is verified by forward-confirmed reverse DNS — rDNS to a hostname, hostname must belong to the operator, then a forward lookup must resolve back to the same IP.

Skipping the forward-confirm is the classic mistake: an attacker controlling their own rDNS can claim any hostname, but cannot make Google's DNS resolve it back to them. Fails closed on any DNS error.

[checking…]

76. Adaptive risk weights

Guard 47's weights are hand-set guesses. Here the honeypots are the labeller: a hit on guard 14 or 15 is ground truth, so every signal co-occurring with it is scored, and weights drift toward what actually predicts automation.

Clamped to 0.5x–1.5x of the base weight and gated on a minimum observation count, so poisoned feedback cannot run away with it.

[checking…]

77. Enumeration / keyspace-coverage detection

Guard 66 asks whether the timing is human. This asks whether the shape of what was requested is — sequential runs, keyspace coverage, monotonic traversal, absence of revisits.

Survives perfect jitter, residential proxies and a flawless fingerprint: it is a property of the intent, not the transport.

[checking…]

78. Steganographic text watermarking

Guard 41's canary dies the moment prose is copied out. This encodes the recipient inside the text with zero-width characters, so a leaked paragraph still traces back.

Not DRM: any non-printing-character normalisation removes it. It is a forensic aid for the lazy-copy case.

[checking…]

79. Degradation response modes

A 403 tells the scraper exactly what happened and what to fix. These cost far more: redirect, empty (200 with a valid but empty result set), and hangup — destroying the socket without replying, which is indistinguishable from a network fault.

Guard 47's ladder also gained a monitor rung below challenge: greylist the client, change nothing they can see.

[checking…]

80. API honeypot (poisoned JSON field)

Guards 14 and 15 only catch crawlers that parse HTML. This catches API clients: an undocumented decoy field that no legitimate consumer has any reason to dereference, because it is in no published schema.

[checking…]

81. Pay-per-crawl (HTTP 402)

The alternative to blocking: charge for access. Priced content answers 402 Payment Required with terms; the crawler pays out of band and presents an HMAC-signed receipt scoped to one path and one crawler.

402 is the status code HTTP reserved for exactly this and never used. Blocking AI crawlers costs you the referral traffic and earns nothing; pricing them keeps both.

[checking…]

82. Per-path crawler policy

"Block all bots" is the wrong granularity. Docs and marketing usually want crawling; monetised pages do not. Policy keys on the verified identity from guard 75 — never the UA string.

[checking…]

83. Sensor data

Guard 36 posts behavioural telemetry as readable JSON, which anyone can hand-write. Every commercial system instead seals its signals into an encrypted, single-use blob — Akamai's _abck, PerimeterX's _px, Imperva's reese84, AWS WAF's aws-waf-token. The scraper cannot author the payload without first reverse-engineering the collector.

[collecting…]

84. Canvas noise detection

Anti-detect browsers defeat canvas fingerprinting by perturbing readback — Camoufox patches Skia's anti-aliasing, seeded per session so the hash stays stable within a visit. That defeats guard 20, and creates a new tell: the noise is keyed to pixel position, so the same glyph drawn at two offsets no longer matches. A stock browser is byte-identical. Brave and Firefox RFP trip this too, which is why it is weighted as texture rather than as evidence.

[probing…]

85. Similarity-relocation trap

Randomizing class names does not stop an adaptive parser: it saves the element's tag, attributes, text, ancestors and sibling index, then relocates by similarity. So /relocate rotates the whole identity vector — and hands the previous response's identity to a decoy. Relocation does not fail; it succeeds onto the wrong element. Anchor on the heading and the itemprop instead and nothing here can move.
