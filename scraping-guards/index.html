Scraping Guards Test Page

Prefer a realistic target? The recipe fixture is an ordinary-looking recipe page — servings calculator, 20 steps, JSON-LD — with a handful of these guards switched on the way a real site would have them.

Every section below is a distinct anti-scraping technique tagged with a data-guard attribute. Protected content is a FLAG-<NAME>-<id> token so a CI scraper can assert exactly what it should and shouldn't be able to reach. See README.md for the expected matrix.

0. Baseline (control)

Plain static text visible to every parser: FLAG-BASELINE-0000

1. JS-rendered content

Injected by client-side JS; absent from raw HTML. [requires JS]

2. Base64-encoded payload

Ships as base64; decoded at runtime. [encoded]

3. ROT13-obfuscated payload

Ships ROT13'd; unscrambled at runtime. [encoded]

4. Text rendered to <canvas>

Drawn as pixels — no selectable/parseable text at all.

5. Shadow DOM encapsulation

Content lives in an open shadow root — outside the light DOM, so a flat HTML parse misses it, though .shadowRoot still reaches it. mode: "closed" would also hide it from page script.
